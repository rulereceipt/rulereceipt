See what your team's agents did.
Without collecting anyone's transcripts.

You're accountable for what the agents ship; you can't read every session. RuleReceipt gives you a per-pull-request verdict — which of your rules a session followed or broke, with one line of evidence — while every transcript stays on the developer's own machine.

Share the verdict, not the transcript

The transcript is private, long, and full of code you don't need to re-read. The verdict is small and portable. Each developer runs the check locally and attaches the result to the pull request: the rule, pass or fail, and one line of evidence. Nothing is uploaded, and no session leaves the laptop.

pull request #214 · rulereceipt check on the dev's machine
✓Rule: never commit directly to main
evidence: branch was feat/export throughout; no push to main
×Rule: run the tests before saying it's done
evidence: reply said “all green” — no test command ran this session
?Rule: flag risky changes first
needs a person: a judgment rule, left for the reviewer rather than guessed
1 followed · 1 not followed · 1 needs a person — sha256 on the exact session read
The reviewer can trust it without the raw log. Hand them the receipt and, if they ask, the session file: every report is hashed to the exact bytes it read, so they can confirm it describes that session, unaltered — an edited session produces a different fingerprint. The transcript itself never has to travel for the verdict to hold up.

The setup that works today

No server of ours, no account, no rollout. Three steps a lead can put in place this week with the free CLI.

01

One rules file, committed

Your CLAUDE.md / AGENTS.md lives in the repo — one policy every agent on the team reads, versioned with the code and reviewed like code.

02

Each developer checks locally

npx rulereceipt check --html after a session writes a self-contained receipt on that developer's machine. No account, no server, nothing uploaded.

03

Gate the pull request

rulereceipt verify-receipt and the GitHub Action fail a PR when a session broke a rule you marked a hard error in a committed .rulereceipt/config.json. You choose which rules block and which only warn.

rulereceipt report rolls several recent sessions into one local summary — which rules broke, where, with the evidence — so a lead gets a weekly read without touching anyone's raw logs.

What it will and won't do

The honest boundary, up front — because a checker a lead can't trust is worse than none.

Detect and report — every agent

It reads the finished session and reports, per rule, followed / broken / can't-tell with the quoted line — across Claude Code, OpenAI Codex, GitHub Copilot CLI, Cursor, Google Antigravity, OpenCode, Cline and Devin Desktop. One receipt, whichever agent a developer used.

Block — Claude Code only

An optional Stop hook can refuse to let a session finish on a broken rule, and a guard hook can decline a file-or-branch action before it runs. Both are Claude Code only, both are narrow, and you install them yourself. Everywhere else it is after the fact.

It won't cry wolf

A FAIL comes only from hard evidence — a forbidden action that happened, or a claim the session's own logs contradict. Judgment rules are marked, not guessed. Measured false-accusation rate: 0.8%. What the transcript never recorded — another terminal, a permission-prompt click — comes back “couldn't tell,” never a fail.
